## 1. `ETAPES.cmd` : codes de sortie explicites

**Constat (Windows).** Dans la livraison 45b1cdb, la forme « commande & goto :eof » renvoyait 0 sous `cmd /c` quand la commande échouait (verify_etapes_cmd : 97 OK, 18 FAIL). Le même principe, `exit /b` explicite, a donc été réécrit pour **toutes** les étapes, nouvelles comprises :

- **Format.** Le fichier est en CRLF : étiquettes et `goto` ne sont pas fiables dans un fichier batch en LF. La règle `.gitattributes` `* -text` conserve ces octets.
- **Aiguillage.** Une ligne `if "%~1"=="<étape>" goto s_<étape>` par étape, puis un bloc étiqueté par étape.
- **Étapes séquentielles.** La commande, puis, sur sa propre ligne, `exit /b %errorlevel%`. Le code est lu après l'exécution de la commande.
- **`latex`.** `if errorlevel 1 (… exit /b 1)` après chaque passage, puis `exit /b 0`.
- **Lancements parallèles** (`ablation-run`, `robustness-run`, `comparators-run`). Le code de chaque `start` est relevé, puis renvoyé par `exit /b %LAUNCH_RC%`. Il couvre le lancement seulement, comme auparavant.
